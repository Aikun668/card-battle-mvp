# 卡牌对战游戏：玩法与交互设计

## 1. 设计目标

本文件把 MVP 的“玩家怎么玩、系统如何响应、什么时候结束”固定下来，作为后续 Python 战斗核心和 Flask 页面实现的共同依据。

本版本只追求一件事：玩家能清楚地完成一局战斗，并且每次出牌都能理解结果。

不在本文件中引入登录、多人对战、卡牌收集、复杂 AI 或复杂动画。

## 2. 玩家核心循环

```text
选择角色
  → 获得初始手牌和能量
  → 查看双方状态
  → 选择卡牌或技能
  → 看到即时结果和战斗日志
  → 结束回合
  → 电脑行动一次
  → 判断胜负
  → 进入下一回合或结果页
```

玩家每回合的核心决策是：

> 在 3 点能量内，决定本回合先攻击、先防守、先治疗，还是保留资源。

## 3. 战斗状态机

### 3.1 状态定义

| 状态 | 含义 | 玩家可做的事 |
|---|---|---|
| `START` | 尚未开始 | 点击开始游戏 |
| `HERO_SELECTION` | 正在选择角色 | 查看角色、选择角色、确认角色 |
| `PLAYER_TURN` | 玩家回合 | 出牌、使用技能、结束回合 |
| `ENEMY_TURN` | 电脑回合 | 只能等待，所有玩家操作禁用 |
| `VICTORY` | 玩家胜利 | 查看结果、重新开始 |
| `DEFEAT` | 玩家失败 | 查看结果、重新开始 |
| `DRAW` | 达到回合上限，平局 | 查看结果、重新开始 |

### 3.2 合法状态流转

```text
START
  → HERO_SELECTION
  → PLAYER_TURN
  → ENEMY_TURN
  → PLAYER_TURN

PLAYER_TURN → VICTORY / DEFEAT / DRAW
ENEMY_TURN  → VICTORY / DEFEAT / DRAW / PLAYER_TURN
结果状态    → START
```

除上面列出的路径外，其他状态跳转都视为非法。

### 3.3 状态保护

每个操作执行前都必须检查当前状态：

- 不是 `PLAYER_TURN` 时，拒绝玩家出牌；
- 不是 `PLAYER_TURN` 时，拒绝玩家使用技能；
- 不是 `PLAYER_TURN` 时，拒绝玩家结束回合；
- 进入 `VICTORY`、`DEFEAT` 或 `DRAW` 后，不再处理战斗操作；
- 页面刷新只重新展示当前状态，不能重复执行上一条操作。

## 4. 战斗初始化

玩家确认角色后，系统创建一份新的 `BattleState`：

- 玩家使用选中的角色；
- 电脑生命值为 28；
- 玩家和电脑的当前护盾为 0；
- 玩家当前能量为 3；
- 电脑当前能量为 3；
- 回合数为 1；
- 玩家固定卡组洗牌后抽 5 张牌；
- 电脑使用固定卡组，不显示电脑手牌；
- 战斗日志写入“战斗开始”和玩家角色；
- 当前状态设置为 `PLAYER_TURN`。

第一回合初始化时已经抽过 5 张牌，不重复抽牌。从第二个玩家回合开始，每个玩家回合开始时抽 1 张牌。

## 5. 玩家回合逻辑

### 5.1 回合开始

进入新的 `PLAYER_TURN` 时：

1. 如果不是第 1 回合，玩家抽 1 张牌；
2. 玩家能量重置为 3；
3. 本回合技能使用次数重置为 0；
4. 更新页面上的手牌、能量和回合数；
5. 写入“第 N 回合开始”。

手牌上限为 6 张。如果手牌已经达到上限，本次抽牌跳过，并在日志中提示“手牌已满”。

### 5.2 出牌

玩家点击某张卡牌后，系统按下面顺序处理：

1. 检查当前是否为 `PLAYER_TURN`；
2. 检查这张牌是否仍在手牌中；
3. 检查当前能量是否不小于卡牌消耗；
4. 扣除卡牌能量；
5. 执行卡牌效果；
6. 将卡牌从手牌移动到弃牌堆；
7. 写入战斗日志；
8. 判断电脑是否已经生命值归零；
9. 如果没有结束，返回 `PLAYER_TURN`，允许继续操作。

玩家一个回合可以连续使用多张牌，只要能量足够。

### 5.3 特殊技能

每个角色每回合最多使用一次特殊技能。

点击技能按钮后，系统检查：

- 当前是否为 `PLAYER_TURN`；
- 本回合是否已经使用过技能；
- 当前能量是否不小于 2；
- 战斗是否仍在进行。

技能合法时扣除 2 点能量，执行角色技能，写入日志，并把技能标记为“本回合已使用”。

### 5.4 结束回合

玩家点击“结束回合”后：

1. 检查当前是否为 `PLAYER_TURN`；
2. 立即把状态改为 `ENEMY_TURN`；
3. 禁用所有玩家卡牌、技能和结束回合按钮；
4. 显示“电脑行动中”；
5. 电脑只执行一次行动；
6. 判断胜负；
7. 如果战斗没有结束，回到下一个 `PLAYER_TURN`。

## 6. 卡牌效果

| 卡牌 | 消耗 | 效果 | 交互反馈 |
|---|---:|---|---|
| 斩击 | 1 | 对电脑造成 6 点伤害 | 电脑生命值减少，日志显示伤害 |
| 重击 | 2 | 对电脑造成 10 点伤害 | 电脑生命值减少，日志显示伤害 |
| 护盾 | 1 | 玩家获得 6 点护盾 | 玩家护盾增加，日志显示护盾 |
| 治疗 | 2 | 玩家恢复 6 点生命值 | 玩家生命值增加，不能超过上限 |
| 火球 | 3 | 对电脑造成 14 点伤害 | 电脑生命值减少，日志显示伤害 |

### 6.1 伤害计算

```text
护盾吸收量 = min(当前护盾, 卡牌伤害)
剩余伤害 = 卡牌伤害 - 护盾吸收量
实际生命值损失 = 剩余伤害
```

也可以等价实现为：

```text
实际伤害 = max(0, 卡牌伤害 - 当前护盾)
```

当护盾被消耗时，先减少护盾，再减少生命值。生命值不能显示为负数。

### 6.2 非法操作提示

| 场景 | 提示文案 |
|---|---|
| 能量不足 | `能量不足，还差 N 点` |
| 卡牌不在手牌 | `这张卡牌已经不能使用` |
| 电脑回合点击卡牌 | `现在是电脑回合，请等待电脑行动` |
| 技能已用过 | `本回合技能已经使用过` |
| 战斗已结束 | `本局已经结束，请重新开始` |
| 手牌已满 | `手牌已满，本回合没有抽到新牌` |

## 7. 电脑回合逻辑

电脑不使用复杂搜索，采用固定优先级，保证行为可预测、容易测试：

1. 如果电脑生命值小于等于 8，且有治疗牌并且能量足够，使用治疗；
2. 否则，如果玩家生命值小于等于 10，使用当前能量允许的最高伤害牌；
3. 否则，如果电脑生命值小于等于 16，且有护盾牌并且能量足够，使用护盾；
4. 否则，使用当前能量允许的最高伤害牌；
5. 如果没有可用牌，电脑直接结束回合。

电脑每个回合只执行一次动作，不连续出多张牌。电脑行动完成后立刻判断胜负，再决定进入结果状态或下一个玩家回合。

## 8. 页面交互

### 8.1 开始页

显示：

- 游戏名称；
- 一句话玩法；
- “开始游戏”按钮；
- 简短规则。

交互：

- 点击“开始游戏”进入 `HERO_SELECTION`；
- 不需要注册、登录或输入复杂资料。

### 8.2 角色选择页

显示：

- 三张角色卡片；
- 角色名称、生命值、特点和技能；
- 当前选中的角色。

交互：

- 点击角色卡片后高亮当前选择；
- 没有选择角色时，“确认角色”按钮禁用；
- 点击“确认角色”后创建战斗并进入战斗页。

### 8.3 战斗页

页面分成四个信息区：

1. 电脑状态区：生命值、护盾、当前行动提示；
2. 中央战斗区：回合数、战斗提示和最近一条日志；
3. 玩家状态区：生命值、护盾、能量、技能按钮；
4. 手牌区：5–6 张卡牌按钮和卡牌说明。

按钮状态：

- 能量足够且当前为玩家回合：卡牌按钮可点击；
- 能量不足：卡牌按钮禁用，并显示消耗；
- 电脑回合：所有玩家操作按钮禁用；
- 技能已使用：技能按钮禁用；
- 战斗结束：所有战斗操作禁用，只保留结果入口。

每次成功操作后立即刷新：

- 生命值；
- 护盾；
- 能量；
- 手牌；
- 回合数；
- 战斗日志。

### 8.4 结果页

显示：

- 胜利、失败或平局；
- 使用的角色；
- 总回合数；
- 关键结果，例如造成伤害、剩余生命值；
- “再来一局”按钮。

点击“再来一局”时清空当前战斗状态，回到角色选择页，不沿用上一局的手牌和生命值。

## 9. 后端与前端请求边界

正式前端通过 `/api` 获取 JSON，页面不自行计算伤害、能量、AI 或胜负。接口的完整字段约定见 [docs/api-contract.md](api-contract.md)。

| 请求 | 作用 |
|---|---|
| `GET /api/heroes` | 获取角色目录 |
| `GET /api/cards` | 获取卡牌目录 |
| `POST /api/game` | 使用 `hero_key` 创建战斗 |
| `GET /api/game` | 获取当前公开战斗状态 |
| `POST /api/game/actions/card` | 使用 `card_id` 出牌 |
| `POST /api/game/actions/skill` | 使用角色技能 |
| `POST /api/game/actions/end-turn` | 结束玩家回合并触发一次电脑行动 |
| `POST /api/game/restart` | 清空当前战斗 |

原有 HTML 页面统一放在 `/demo` 下，仅用于本地联调和人工验收；正式页面由后续插件基于 `/api` 重新设计。

## 10. MVP 验收场景

### 场景 A：正常出牌

1. 选择战士；
2. 进入战斗，看到 5 张手牌和 3 点能量；
3. 使用一张斩击；
4. 电脑生命值减少 6，能量减少 1，斩击进入弃牌堆；
5. 战斗日志出现对应记录。

### 场景 B：能量不足

1. 当前只有 1 点能量；
2. 点击火球；
3. 卡牌不从手牌消失；
4. 电脑状态不变化；
5. 页面提示能量不足。

### 场景 C：结束回合

1. 玩家点击结束回合；
2. 页面进入“电脑行动中”；
3. 玩家按钮全部禁用；
4. 电脑只执行一次动作；
5. 战斗未结束时进入下一次玩家回合。

### 场景 D：战斗结束

1. 玩家造成足够伤害使电脑生命值归零；
2. 页面进入结果页；
3. 所有战斗操作不可用；
4. 点击再来一局后回到角色选择页；
5. 新一局拥有新的手牌、生命值和回合数。

## 11. 实现顺序

1. 先实现 `BattleState` 和状态流转；
2. 再实现卡牌效果、能量、护盾和胜负判断；
3. 为核心规则编写自动化测试；
4. 实现电脑的固定优先级 AI；
5. 接入 Flask 路由；
6. 实现四个页面和按钮状态；
7. 最后再做视觉样式、动画和演示优化。
