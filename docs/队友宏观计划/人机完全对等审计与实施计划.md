# 人机完全对等审计与实施计划

> 审计基线：`930aa8e feat: expose utility AI difficulty settings`；2026-09-20 本地自动化测试 `102 passed`。

## 对等的定义

这里的“人机完全对等”不是要求玩家和 AI 做出相同选择，也不是取消难度选项，而是要求：

> 双方在同一局中拥有相同的公开信息范围、相同的英雄池、相同的卡组、相同的资源、相同的可行动作、相同的响应权、相同的状态持续规则，以及公平的先后手机制。

AI 只负责代替电脑在它自己的合法选项中作决定。简单、中等、困难只能影响 AI 的决策质量，不能改变任何比赛规则或让 AI 读取玩家私有信息。

## 当前已经对齐的规则

以下规则目前双方已经基本一致，应在重构时保留：

| 规则 | 当前状态 |
|---|---|
| 初始手牌 | 双方都是 5 张 |
| 手牌上限 | 双方都是 6 张 |
| 每轮补牌 | 电脑回合结束后双方各抽 1 张，等价于各自在下一次行动前补 1 张 |
| 基础卡牌费用和效果 | 普通攻击、护盾、治疗共用同一份卡牌定义 |
| 伤害与治疗 | 都先扣护盾、再扣生命；治疗不超过生命上限 |
| 连续出牌 | 电脑会在能量允许时重新评分并连续出牌，玩家本来就可连续出牌 |
| 终局停止 | 任一方生命归零后，电脑不再继续行动 |
| 难度数值 | 三档难度不额外增加生命、伤害、能量或抽牌 |

## 本轮明确采用的比赛规则

### 英雄与起手

- 玩家从现有三个英雄中选择一名。
- 电脑从同一英雄池中独立随机选择一名；允许与玩家使用相同英雄。
- 电脑选择不读取玩家选择结果来进行克制，不增加“AI 后手反选”。
- 双方各自使用所选英雄的生命值和技能。
- 双方各自洗同样的 13 张固定牌库并抽 5 张。
- 会话 RNG 随机决定本局首个行动方；测试可指定首个行动方以稳定验证。

### 回合、能量、护盾与抽牌

- 轮到某一方开始自己的行动回合时，该方能量恢复为 3、该方技能使用次数重置；首回合的行动方不额外抽牌。
- 从各自第二个行动回合开始，该方在回合开始抽 1 张牌；双方手牌上限均为 6。
- 一方结束回合后，未使用能量保留到对方回合，只能用于该方的响应牌；当该方下次行动回合开始才恢复为 3。
- 双方护盾只在受到伤害时被消耗，不会因为轮到谁而自动清零。

### 行动与响应

- 双方在自己的行动回合都有：使用任何费用足够的普通牌、使用一次费用足够的英雄技能、结束回合。
- 任一攻击牌被打出后，在结算伤害前检查防御方是否拥有可用闪避和足够能量。
- 防御方是玩家时，前端显示“使用闪避 / 放弃响应”；防御方是电脑时，AI 在“闪避 / 放弃”候选中评分选择。
- 每次攻击最多有一次闪避响应；不在本阶段引入反击链或多层响应。

### 信息边界

- 私有信息：自己手牌、自己抽牌堆顺序。
- 公开信息：双方英雄、生命、护盾、能量、技能是否已使用、行动日志、固定牌表、已打出的牌。
- AI 只能读取电脑私有信息和公开信息；不得直接读取玩家当前手牌或玩家抽牌堆顺序。
- 浏览器继续不接收电脑手牌和电脑抽牌堆；这不是不公平，而是双方各自保留手牌的正常隐藏信息规则。

## 实施顺序

1. 先建立可表示“两名英雄参与者”的通用状态模型，并把旧 session 平滑迁移。
2. 再统一牌库、起手、首手、抽牌、能量、护盾和结束回合规则。
3. 将卡牌与英雄技能结算改成按参与方通用执行，AI 候选接入技能与真正的 `pass`。
4. 将单向 `RESPONSE` 改成通用的攻击方 / 防御方响应事件，并让 AI 处理电脑响应。
5. 用受限的 AI 观察视图取代直接把整个 `BattleState` 交给评分函数，杜绝读玩家手牌。
6. 最后扩展 API 与页面公开信息，更新文档、自动化测试和人工对局验收。
