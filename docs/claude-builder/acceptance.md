# 卡牌对战游戏 MVP 验收与质量门槛

## 1. 目的

这份文档用于在演示、提交课堂作业或交给下一个开发者前，过滤大部分逻辑错误、代码问题和页面交互问题。

验收原则只有一条：**任何硬门槛失败，当前版本都不能称为完成。**

## 2. 验收顺序

按下面顺序执行，不要只打开网页试玩几下：

1. 安装依赖；
2. 静态检查和语法编译；
3. 自动化测试；
4. Flask 路由与会话测试；
5. 手动完整对局；
6. Git 工作区检查；
7. 记录结果。

## 3. 硬门槛：代码质量

在项目根目录依次运行：

```bash
python -m compileall app.py api_routes.py demo_routes.py web_support.py game
ruff check .
ruff format --check .
pytest -v
```

通过标准：

- `compileall` 没有语法错误；
- `ruff check .` 没有错误；
- `ruff format --check .` 没有格式差异；
- `pytest -v` 的所有测试通过；
- 测试输出中没有跳过的核心规则测试，也没有未处理的 warning 或 traceback。

若 `ruff` 报错，只允许修改被报告的问题并重新运行整套命令；不要为了让检查通过而禁用规则或删除测试。

## 4. 自动化测试覆盖要求

### 4.1 卡牌与角色数据

必须有测试验证：

- 只有战士、法师、游侠三个角色；
- 三个角色的最大生命值分别是 32、24、27；
- 基础卡牌为斩击、重击、护盾、治疗、火球，另有响应牌闪避和装备牌长剑、铁甲；
- 每个英雄各有一副固定卡组，都刚好 16 张且只从公开牌表取牌；配比为战士斩击 6 / 重击 3 / 护盾 2 / 治疗 1 / 闪避 1 / 长剑 1 / 铁甲 1 / 破甲 1、法师火球 3 / 重击 3 / 斩击 4 / 护盾 2 / 治疗 1 / 闪避 1 / 铁甲 1 / 蓄力 1、游侠斩击 8 / 重击 2 / 护盾 1 / 治疗 1 / 闪避 2 / 长剑 1 / 处决 1；
- 闪避不进入任何一方的主动出牌候选：双方都只能在自己的攻击被响应窗口拦下时使用它；
- 每张装备牌都有明确归宿的装备槽（`EQUIP_SLOTS` 覆盖全部装备牌，槽位只有武器和护甲两种）；
- 卡牌消耗与效果数值符合 `docs/mvp.md`。

### 4.2 战斗规则

必须有测试验证：

- 新对局的先手由 RNG 决定；创建接口返回玩家回合、响应窗口或终局，电脑先手时它开局的回合在创建流程里跑到需要玩家决定的点为止（响应窗口留给玩家自己响应，绝不替他放弃）；
- 双方英雄都从同一个英雄池随机/选择产生，最大生命值取自各自英雄（战士 32、法师 28、游侠 27），初始能量都是 3，各拿 5 张初始手牌；
- 护盾先吸收伤害，剩余伤害才扣生命值；
- 生命值不为负，治疗不超过最大生命值；
- 成功出牌会扣能量、移出手牌、进入弃牌堆并写入日志；
- 能量不足时，生命值、手牌、弃牌堆、能量和日志都不能变化；
- 不属于自己手牌的卡不能使用；
- 每回合技能只能使用一次，双方都有英雄技能且共用 2 点能量的消耗；
- 电脑归零后立刻进入 `VICTORY`，玩家归零后立刻进入 `DEFEAT`；
- 终局后再次出牌、使用技能、结束回合或响应都被拒绝；
- 手牌上限为 6；
- 抽牌堆耗尽时，只在弃牌堆存在时洗回抽牌堆；
- 护盾跨回合保留，不随回合开始清零，双方一致；
- 第 10 回合结束时按生命值判胜负：血多的一方获胜；生命值相同再比剩余护盾，护盾厚的一方获胜；两者都相同才进入 `DRAW`；
- 伤害牌在防御方有闪避和能量时挂起为 `RESPONSE`，响应只决定这次伤害落不落地，费用与弃牌在挂起前已结清；
- 装备牌花 1 点能量打出后进入对应的装备槽，**不进入弃牌堆**；打出装备不会改变生命值和护盾；
- 装备跨回合保留，回合开始只重置“本回合是否已触发”，不会把装备本身清掉；
- 长剑只加成斩击：斩击 +2，重击、火球等其它伤害牌不受影响；加成后的伤害同时体现在挂起攻击的 `damage`、结算扣血和日志数字上；
- 铁甲先于护盾减伤，且对英雄伤害技能同样生效；被护盾完全吸收的伤害也算用掉了本回合的铁甲；
- 长剑加成和铁甲减伤都是每回合一次，触发后同一回合内不再生效，下个自己回合重新可用；
- 闪避成功时这一下完全不结算：铁甲不会被消耗，护盾和生命值都不变；
- 任何时刻“手牌 + 抽牌堆 + 弃牌堆 + 装备槽”恒等于该方英雄那整副 16 张牌（随机对局的不变量断言覆盖装备区）；
- 装备随存档往返保留；旧存档（没有装备字段）读出空装备且不报错；
- 破甲对无护盾目标造成 4 点伤害、对有护盾目标造成 8 点（先削盾，剩余落在生命上）；
- 处决在目标生命低于其最大生命 30% 时翻倍（2 费 8 → 16），高于或等于 30% 时维持 8；
- 蓄力打出后，下回合能量为 3 + 结余并一次性清零；结余可叠加、随存档往返保留、旧存档读出 0；
- 三张条件牌各归一副牌组，每副 16 张；卡表共 11 张，每张牌都至少有一副牌组在用；
- 处决是消耗牌：打出后进入移除区（不进弃牌堆、洗牌不再出现、被闪避照样移除）；2 费 8 伤、目标低于 30% 生命时 16 伤；
- 五区守恒：任何时刻"手牌 + 抽牌堆 + 弃牌堆 + 装备槽 + 移除区"恒等于该方英雄的整副 16 张牌；移除区随存档往返保留、旧存档读出空列表。

### 4.3 电脑 AI 与回合切换

必须有测试验证：

- 电脑先枚举合法候选（费用足够的手牌 + 英雄技能 + 结束回合），再评分、排序、选择；
- 攻击评分考虑实际伤害、击杀、伤害溢出、目标护盾和能量效率：能量刚好击杀时不会选择更高费用、伤害溢出的牌；
- 治疗只在真正恢复生命时得分，接近满血的治疗低于普通攻击；
- 已有大量护盾时继续叠盾的评分低于有实际收益的行动；
- 面对高护盾玩家时电脑仍然持续攻击，不会因为伤害被吸收就永久空过；
- 没有合法卡牌时电脑结束回合；
- 电脑每打完一张牌都用最新状态重新评分，因此可以像玩家一样一回合连出多张牌；
- 电脑连续出牌受同一套能量规则限制，不会超出能量出牌；
- 电脑生命归零或玩家生命归零后立刻停止剩余行动；
- 电脑行动后，战斗未结束时回合数加 1、玩家能量重置为 3、技能使用标记重置；
- 电脑回合不能被玩家出牌请求改变；
- 相同种子和相同状态下，简单 / 中等 / 困难的随机选择稳定可复现，困难稳定选择评分最高的行动；
- 电脑的决策输入（`AIObservation`）里没有玩家手牌和抽牌堆，类型上就没有存放它们的位置：只改玩家隐藏手牌，观察值、评分和排序结果都不变；
- 困难模式的一步前瞻只按公开牌表取伤害上界，不读玩家手里握着哪张牌，也不拿公开弃牌收窄范围；
- 电脑不会为了难度权重白扔闪避：这一击全被护盾吃掉、闪避救不回任何生命时，三档难度都不闪避；
- 电脑会主动留住最后 1 点能量给手里的闪避，中等和困难尤其明显；
- 电脑把装备牌当作普通候选评估，走的是同一套评分和选择流程，没有专门的装备分支；
- 长剑的评分按手里剩下几张吃加成的斩击算，且封顶两次（一回合只触发一次，攒再多也吃不完）；手里一张斩击都没有时武器评分为 0，低于空过；
- 铁甲的评分随失血比例上升，濒死时比满血时值钱；
- 电脑装上长剑后，斩击的评分随之提高；本回合已经用掉加成后回到原值；
- 电脑身上的铁甲会从它对玩家下回合伤害上界的估计里减掉 2；本回合已用掉的不再减；
- 电脑的装备和它的装备触发状态都在 `AIObservation` 里，双方对称可见，玩家手牌依然进不去；
- 电脑会对伤害牌做连招规划：法师电脑手里有火球 + 斩击、技能可用时，中等与困难打出"技能（10）+ 斩击（6）= 16 伤"的序列，而不是单张火球的 14 伤；简单难度不规划，维持逐张贪心；
- 规划深度按难度分层（简单 0 / 中等 1 层 / 困难 3 层），只读取 `AIObservation`，不改变真实对局状态；
- 武器装备参与规划但只统计它能加成的伤害牌：先穿长剑再打斩击能拿到加成，长剑旁边只有火球时不会被误判成值得先穿；
- 规划版本的整局不变量成立：AI 驱动的随机对局里能量非负、双方"手牌 + 抽牌堆 + 弃牌堆 + 装备槽"恒等于各自英雄的整副 16 张；
- 玩家回合的公开状态带 `enemy.intent`（`kind` / `source` / `name` / `value` / `text`），响应窗口与终局时为 `null`；同一局面重复读取逐字节相同；
- 读取意图不改变对局：三档 2400 局的对局读数与加功能前逐字相同；
- 攻击意图的伤害含未消耗的武器加成，与真实结算一致；意图只能指向电脑手牌里有的牌或它自己的技能；
- 只改玩家隐藏手牌时意图不变；意图不包含电脑手牌数量、抽牌堆或弃牌堆内容；
- 破甲与处决的 AI 评分走与结算相同的条件伤害入口（"AI 预测 = 真实结算"有专门测试）；有盾时破甲反超斩击、无盾时劣于斩击；
- 蓄力是合法候选且分数为正，但不参与伤害连招规划（分数等于战术分）；意图预告的能量预演含蓄力结余；
- 玩家威胁上界按对手当前公开状态展开条件伤害：满血时是火球 14，残血（低于 30%）时是处决 16；
- `/api/cards` 的每张卡牌带 `exhaust` 标记；公开状态下双方都带 `exhaust_pile`。

### 4.4 难度选择

必须有测试验证：

- `POST /api/game` 不传 `ai_difficulty` 时默认 `medium`；
- 传 `easy` / `medium` / `hard` 时对局按该难度创建，并随公开状态返回；
- 传其他值返回 422 且错误码为 `INVALID_DIFFICULTY`；
- 难度随对局保存进 session，读取与刷新后不丢失；
- 旧 session 缺少难度字段时按 `medium` 处理，不返回 500。

### 4.5 会话、数据库与路由

必须有测试验证：

- `BattleState` 序列化后再还原，状态、手牌、回合数、日志和阶段完全一致；
- 没有进行中的对局时，访问战斗操作会跳转到选角页，不返回 500；
- 选择角色后，临时联调页面以 `POST /demo/heroes` 重定向到 `/demo/battle`；
- 临时联调页面使用卡牌、技能、结束回合和响应都使用 POST 后重定向；正式前端使用 `/api` JSON 接口；
- 刷新 `/demo/battle` 与 `GET /api/game` 只重新展示当前状态，不能重复执行上一次动作；
- 公开状态对双方输出同一组字段（血量、护盾、能量、英雄、技能状态、装备），只给玩家输出 `hand`；
- 公开状态的 `equipment` 双方对称，`weapon` / `armor` 两个键始终存在、没装备时为 `null`，装上装备后带卡牌定义；电脑的装备可见而电脑的手牌依然不可见；
- 刷新后双方的英雄、能量、技能次数和挂起的响应窗口都不丢失；
- 旧版扁平 session（没有 `participants` 分区）仍能读出公开状态，不返回 500；
- 对局终局结果只写入 SQLite 一次；
- 重新开始会清除旧对局状态，并回到角色选择页；
- SQLite 数据库文件只保存在 `instance/`，不被 Git 跟踪。

## 5. 代码审查清单

在提交前人工阅读以下内容：

| 检查点 | 必须满足 |
|---|---|
| 规则位置 | 卡牌、伤害、回合和胜负逻辑位于 `game/`，不能写在 HTML 模板或 HTTP 路由里 |
| 可变状态 | 不使用模块级全局 `BattleState` 保存不同玩家的对局 |
| 前置校验 | 每个战斗动作先检查阶段、卡牌归属、能量和终局状态，再修改数据 |
| 错误反馈 | 失败操作返回中文明确原因，不吞掉异常或静默失败 |
| 数据库 | SQL 使用参数绑定；数据库连接使用上下文管理器关闭 |
| 会话数据 | Flask session 中只保存 JSON 安全的字典、列表、字符串、数字和布尔值 |
| 路由 | `/api` 的状态改变接口是 POST；`/demo` 页面状态改变接口是 POST 并遵循 Post/Redirect/Get |
| 模板 | 模板只负责展示与提交表单，不计算伤害、不决定电脑出牌 |
| 范围控制 | 不新增多人、登录、抽卡、商城、外部 AI API 或未批准功能 |

## 6. 手动验收：完整对局

启动应用：

```bash
flask --app app:create_app run --debug
```

按顺序完成以下场景：

| 场景 | 操作 | 预期结果 |
|---|---|---|
| 开始流程 | 打开首页，点击开始游戏 | 进入角色选择页，能看到 3 个角色 |
| 选角保护 | 未选择角色时尝试确认 | 确认按钮不可用或页面给出明确提示 |
| 创建战斗 | 选择任意角色并确认 | 进入战斗页，显示双方英雄、生命值、护盾、能量、5 张手牌、回合数和日志 |
| 正常出牌 | 使用一张能量足够的攻击牌 | 能量减少，电脑生命值变化，卡牌离开手牌，日志新增一行 |
| 不足能量 | 将能量用到不足后点击高费用牌 | 卡牌与战斗状态不变化，出现“能量不足”提示 |
| 技能限制 | 使用一次技能后再次点击技能 | 第二次被拒绝，出现“本回合技能已经使用过”提示 |
| 回合交接 | 点击结束回合 | 玩家按钮不可用，电脑按能量连续行动后进入下一玩家回合或结果页 |
| 响应攻击 | 手里留一张闪避，结束回合等电脑攻击 | 出现“使用闪避 / 放弃响应”入口；闪避后扣 1 点能量、生命与护盾不变，放弃则按护盾优先扣血 |
| 装备 | 抽到长剑或铁甲并打出（多开几局能遇到） | 扣 1 点能量、手牌少一张、日志出现装备记录，生命与护盾不变；这张牌不会进弃牌堆，之后同一张不会再被抽到。前端本轮不展示装备槽，装备效果要看日志与伤害数字 |
| 电脑先手 | 多开几局，遇到电脑先手的对局 | 创建后直接进入玩家回合，日志里能看到电脑开局做了什么，双方资源都能在页面上看到 |
| 信息公开 | 观察双方状态区 | 双方的英雄、生命值、护盾、能量和技能状态都可见；电脑手牌从头到尾不出现 |
| 难度选择 | 在 `/demo` 选角时分别用简单、中等、困难各开一局 | 三局都能开始，电脑名称旁显示的难度与选择一致，刷新后不变，双方数值完全相同 |
| 页面刷新 | 在出牌后的 `/demo/battle` 页面刷新两次 | 生命值、手牌、日志和回合数不额外变化 |
| 终局 | 将一方生命值打到 0 或打满 10 回合 | 进入正确结果页，战斗按钮不再可用 |
| 重新开始 | 点击“再来一局” | 回到选角页，旧手牌、生命值和回合数不被保留 |

检查完后停止本地服务器。

git status --short
git log --oneline --decorate -8

## 8. Bug 分级和处理

| 级别 | 示例 | 处理要求 |
|---|---|---|
| 阻塞 | 不能开始游戏、出牌后 500、结果错误、刷新重复扣血 | 必须修复并补自动化回归测试，才能交付 |
| 严重 | 能量不足仍能出牌、AI 一回合内超出能量出牌、AI 生命或玩家生命归零后仍继续行动、终局还能操作 | 必须修复并补自动化回归测试，才能交付 |
| 一般 | 按钮提示不清楚、日志少了行动方、页面在窄屏溢出 | 修复后重新跑相关测试和手动场景 |
| 轻微 | 文字间距、颜色或卡牌边框不一致 | 可集中修复，但不得影响规则和可读性 |

任何阻塞或严重问题都不能用“课堂作业可以先这样”作为交付理由。
