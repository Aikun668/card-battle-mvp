# 卡牌对战前端优化指南

> 用途：记录本项目后续的前端优化项、边界、实施顺序与验收标准。以后每一轮优化都在本目录新增独立的 Markdown 记录，不把讨论结论散落在代码注释或聊天记录里。

## 当前基线

- 页面采用固定 `1920 × 1080` 游戏舞台，浏览器只对整张舞台等比例缩放。
- 后端使用 Flask；游戏规则、状态接口和出牌逻辑已经可用。
- 手牌以“卡框 + 内嵌 Artwork”的方式呈现，Artwork 不再作为卡牌顶部的独立图片。
- 页面视觉基准为深色奇幻卡牌战斗界面。

## 已完成项

### P1-01 下半区收紧

### 已解决的问题

玩家信息区与手牌区之间的视觉距离偏大，导致下半区像被拆成两段，主操作区不够集中。

### 已采用方案

只将 `.hand-zone` 向上收紧 `18px`；不改卡牌尺寸、素材、上半区、游戏逻辑或接口。

### 验收结果

- 手牌整体更靠近玩家信息区。
- 卡牌底边仍完整显示，页面没有纵向滚动。
- 固定 16:9 舞台、卡牌比例和原有交互保持不变。

### P1-02 至 P1-04：右侧操作栏、能量反馈与结束回合归位

#### 实施结果

- 右侧形成“战斗日志 → 当前卡牌预览”的明确层级。
- 当前卡牌预览由手牌 `hover / focus` 更新；手牌点击仍保持即时出牌。
- 预览区展示卡牌名称、类型、效果、`⚡ 消耗` 与可用/能量不足状态。
- 所有手牌与英雄技能在能量不足时提前置灰，并显示“需要 N，当前 M”。
- 英雄技能与结束回合被收为同一组右侧操作控件；英雄技能的图标、说明与能量徽记同步加强。

#### 验收证据

- 自动测试：`45 passed`。
- 浏览器控制台：`0 errors, 0 warnings`。
- 正常状态截图：`output/playwright/p1-operation-rail-fit.png`。
- 能量不足截图：`output/playwright/p1-energy-insufficient.png`。

## 待优化问题与方案

### P1-02 右侧操作区缺少明确层级（已完成）

#### 问题

当前右侧同时承担战斗日志、英雄技能和结束回合，但它们之间缺少清晰的“操作路径”。英雄技能按钮的视觉重量偏弱，结束回合也显得悬在中右区域。

#### 方案

将右侧定位为固定的操作栏，视觉顺序为：

```text
战斗日志
当前卡牌信息（预览区）
英雄专属技能
结束回合
```

- 战斗日志维持顶部，不改变内容来源。
- 在日志下方新增/预留“当前卡牌信息”区域，显示名称、效果、类型与能量消耗。
- 英雄技能改成更大的动作卡，图标、名称、效果、消耗一眼可读。
- 结束回合下沉，与手牌区和英雄技能组成同一个操作闭环。

#### 边界

- 先只调整前端布局与显示，不改 Flask、API、数据库或战斗结算。
- 当前点击手牌会立即出牌；第一版详情区使用 `hover / focus` 预览或最近交互卡牌同步，避免未经确认就改成“两次点击出牌”。

#### 验收

- 右侧从上到下可读出“信息 → 当前选择 → 技能 → 结束回合”的顺序。
- 结束回合不再像独立漂浮按钮。
- 不影响现有日志更新、英雄技能点击和结束回合请求。

### P1-03 能量消耗的语义不够明确（已完成）

#### 问题

手牌左上角数字已经存在，但用户不一定能理解它代表能量消耗；英雄技能的消耗信息也不够突出。玩家可能要尝试点击后才知道能量不足。

#### 方案

统一所有可执行动作的能量表达：

- 手牌左上角圆形数字保留，并在详情区明确写为“消耗 N 点能量”。
- 手牌 `hover / focus` 时显示同样的消耗说明；不可用时保留可读的禁用原因。
- 英雄技能动作卡显式展示 `⚡ N` 与文字“消耗 N 点能量”。
- 能量不足时保持禁用态，并给出“需要 N，当前 M”的前端提示。

#### 边界

- 能量判断仍以现有后端状态为准，不在前端复制或改变规则。
- 不改变卡牌消耗数值、能量上限或技能次数限制。

#### 验收

- 玩家无需猜测即可知道任意卡牌和英雄技能的能量成本。
- 能量不足时，用户能在点击前理解原因。

### P1-04 结束回合按钮的归属感不足（已完成）

#### 问题

结束回合是本回合的最终确认动作，但当前位置与手牌和技能操作的联系不够强。

#### 方案

- 将按钮固定在右侧操作栏的底部，并在垂直位置上贴近手牌区。
- 保留金色主按钮风格，但让按钮宽度、高度和周围留白与英雄技能动作卡成组。
- 禁用、悬停和可用状态继续沿用现有逻辑，只增强视觉状态。

#### 验收

- 用户可以从手牌自然扫视到技能，再到结束回合。
- 不遮挡手牌、日志或角色信息。

### P2-01 英雄专属技能按钮需要成为主操作控件（已完成）

#### 问题

英雄技能目前更像普通信息条，图标、效果和消耗的阅读优先级都偏弱。

#### 方案

- 提高按钮最小高度与图标尺寸。
- 使用三段结构：`图标`、`技能名 + 效果 + 消耗说明`、`醒目的能量徽记`。
- 用边框、背景和可用态强调它是可点击技能，而不是纯状态文字。

#### 实施结果

- 技能图根据当前英雄动态匹配：战士使用护盾图，法师使用火球图，游侠使用攻击图。
- 技能卡已放大图标与整体高度，并明确分出技能名、技能效果、使用状态和能量消耗。
- 保留原有技能点击、能量判断、每回合限用一次和结束回合逻辑，仅调整前端展示。

#### 验收

- 首次进入战斗时，用户能够把它识别为英雄专属可执行动作。
- 它不会压过结束回合的最终确认层级。

#### 验收证据

- 自动化测试：`pytest -q` → `45 passed`。
- 浏览器截图：`output/playwright/p2-01-skill-card.png`。
- 浏览器控制台：0 errors，0 warnings。

### P2-02 卡牌底部信息锚点偏弱（已完成）

#### 问题

卡牌名称、效果和“攻击 / 防御 / 辅助”类型标签已经存在，但类型标签偏小、偏淡，卡牌底部不够稳定。

#### 方案

- 保持顺序：名称 → 效果 → 类型标签。
- 增加类型标签的最小宽度、内边距、对比度与边框存在感。
- 不让标签伪装成新的可点击按钮；它仍是只读分类信息。

#### 实施结果

- 类型标签固定最小宽度并禁止换行，缩放后仍能作为卡牌底部的稳定锚点。
- 所有类型统一使用低饱和灰米色按钮，不按攻击、防御、辅助额外染色。
- 在卡牌名称下方增加淡色细分隔线，并拉开名称、效果和按钮之间的阅读距离。
- 只调整 `.card-type` 的展示样式，没有修改卡牌尺寸、Artwork、出牌逻辑或接口。

#### 验收证据

- 自动化测试：`pytest -q` → `46 passed`。
- 浏览器截图：`output/playwright/p2-02-card-title-spacing-final.png`。
- 五张手牌的类型标签均完整显示，按钮统一、未发生换行、遮挡或 Artwork 挤压。
- 卡牌名称与效果之间存在淡色分隔线，底部按钮与上方内容保留明确间距。
- 卡牌名称在 Artwork 底线与分隔线之间下移 6 个设计像素，视觉位置更居中。

#### 验收

- 缩小舞台后，类型标签仍然容易辨认。
- 不挤压 Artwork，也不破坏卡牌既定宽高比。

### P2-03 手牌缺少主操作区的反馈（已完成）

#### 问题

现有手牌可用，但排列过于平直，悬停、焦点与禁用态的区别还不够强，缺少“我现在准备出这张牌”的反馈。

#### 方案

- 保留当前整体居中、固定比例与 Artwork 裁切方式。
- 强化 hover / focus 的抬升、阴影和金色描边。
- 让禁用牌保持可识别，但降低饱和度与亮度。
- 第一阶段不增加选牌后确认按钮；如要加入两段式“选牌 → 确认出牌”，必须先单独确认交互规则。

#### 实施结果

- 可用手牌在 hover 和键盘 focus 时会抬升、放大少量，并获得金色描边和阴影反馈。
- 能量不足牌与非玩家回合牌采用不同强度的低饱和禁用态，仍可辨认 Artwork、名称、效果和消耗。
- 复用现有 `data-availability` 状态与 hover / focus 预览逻辑；没有改变即时出牌行为，也没有新增确认按钮。

#### 第 1 项：轻微扇形排列（已完成）

- `renderHand` 根据当前手牌数量与索引相对整组中心的位置动态计算布局变量。
- 两侧最大旋转为约 `±3°`，最大下沉为 `8px`；奇数张手牌的正中卡保持水平，偶数张手牌由中间两张平缓过渡。
- 保持现有卡牌尺寸、间距与素材，不写死单张卡牌坐标。

#### 验收

- 鼠标经过与键盘聚焦时，当前目标卡明显可辨。
- 同一手牌中，禁用卡与可用卡的差异清晰。
- 点击行为保持现有即时出牌逻辑。

#### 验收证据

- 自动化测试：`pytest -q` → `49 passed`。
- 可用牌 hover：`output/playwright/p2-03-hand-ready-hover.png`。
- 键盘 focus：`output/playwright/p2-03-hand-keyboard-focus.png`。
- 能量不足与缩放验收：`output/playwright/p2-03-hand-energy-disabled.png`、`output/playwright/p2-03-hand-scaled-energy-disabled.png`。
- 手牌数量动态验收：`output/playwright/p2-03-hand-fan-five-cards.png`、`output/playwright/p2-03-hand-fan-four-cards.png`。

#### 第 4 段：能量不足状态（已完成）

- 玩家回合内，能量不足的手牌仍保留点击反馈，但不会调用出牌接口，也不会改变战斗状态。
- 点击后只在固定游戏舞台中央显示：`能量不足：需要 X 点，当前 Y 点。`
- 非玩家回合和结算态继续保持原生禁用，现有卡牌数据结构、后端规则与接口不变。

#### 第 4 段验收证据

- 浏览器截图：`output/playwright/p2-03-energy-insufficient-toast.png`。

### P3-01 当前选中卡牌详情与高级反馈

#### 可选增强

- 右侧详情区随 hover / focus 预览卡牌数据。
- 牌打出后短暂显示“刚使用：卡牌名 / 实际效果”。
- 能量不足提示与按钮置灰采用统一文案和状态色。
- 为技能、出牌和结束回合补充细微的边框/光效反馈。

#### 决策点

若改为“点击卡牌只选中，第二次确认才出牌”，这会改变现有交互流程，必须在实施前单独确认。

## 推荐实施顺序

1. P1-02：建立右侧操作栏和当前卡牌预览区的占位结构。
2. P1-03：统一手牌与英雄技能的能量说明。
3. P1-04：将结束回合纳入右侧操作栏底部。
4. P2-01：强化英雄技能动作卡。
5. P2-02：增强卡牌底部类型标签。
6. P2-03：补齐手牌 hover / focus / 禁用状态。
7. P3-01：在不改变即时出牌规则的前提下完善详情反馈。

每一步都应单独截图对照，并在固定 `1920 × 1080` 舞台与至少一个缩放浏览器尺寸下验收。

## 实施约束

- 保持固定 16:9 舞台及整体等比例缩放机制。
- 保持 Flask 路由、API 契约、数据库、回合流程、卡牌消耗和结算逻辑不变。
- 尽量只修改 `templates/game.html`、`static/game.js` 与 `static/game.css` 的展示层；任何新增前端状态都必须从现有公开状态派生。
- 不以临时负边距或任意绝对定位堆叠解决结构问题；布局改动必须能说明所属区域和验收结果。
- 每个优化记录需写明：目标、改动范围、未改动范围、截图路径、测试结果和待确认项。
