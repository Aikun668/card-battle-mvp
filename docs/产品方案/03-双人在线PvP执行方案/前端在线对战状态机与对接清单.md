# 在线 PvP 前端状态机与对接清单

> 上层依据：[执行总览与契约门禁](执行总览与契约门禁.md)。  
> 唯一接口依据：[在线PvP接口契约-v1](../../接口契约/在线PvP/在线PvP接口契约-v1.md)。  
> 范围：定义前端页面状态、请求映射、轮询和错误恢复；不定义战斗数值、座位身份或 HTTP 字段含义。

## 1. 前端的唯一事实来源

在线 PvP 页面只有一个业务状态对象：接口返回的 `RoomSnapshot`。前端本地只允许保存：

- 最新 `RoomSnapshot`；
- 当前网络请求是否进行中；
- 轮询计时器；
- 纯界面状态，例如当前输入的昵称、已选择但尚未提交的英雄、提示消息和弹窗开关。

前端不得保存或推导：对手手牌、战斗规则结果、当前座位、赢家、房间 revision 的下一值。它们均以服务端快照为准。

每次成功读取或动作响应后，必须整体替换本地快照，不得对旧快照局部打补丁。`409 STALE_STATE` 与带快照的 `422` 同样要整体替换，然后由用户决定是否重新操作；前端不得自动重放动作。

## 2. 页面与接口入口

正式开始页只提供下列入口：

| 用户动作 | 接口 | 成功后的前端去向 |
|---|---|---|
| 人机对战 | 既有 `/api/game` | 既有人机页面；不走在线房间状态机。 |
| 创建双人房间 | `POST /api/rooms` | 进入创建者自己的房间页，显示房间码、邀请链接和等待态。 |
| 加入双人房间 | `POST /api/rooms/join` | 进入加入者自己的同一房间页，进入盲选。 |
| 通过邀请链接进入 | 先从 URL 读取 `room_code`，再调用 join | 与“加入双人房间”相同。 |

创建和加入只提交契约定义的 `nickname`、`room_code`；不提交 `seat`、`viewer`、英雄、房间状态或任意座位相关字段。

## 3. 页面状态机

```text
大厅
├─ 创建成功 → WAITING
└─ 加入成功 → HERO_SELECT

WAITING
  → 对方加入（轮询） → HERO_SELECT
  → 过期 → EXPIRED

HERO_SELECT
  → 自己锁定，等待对方
  → 双方锁定（响应或轮询） → PLAYING
  → 过期 → EXPIRED

PLAYING
  ├─ 自己回合 / 自己响应 → 可操作
  ├─ 等对方行动 → 轮询
  └─ 终局 → FINISHED

FINISHED
  ├─ 自己确认再来一局 → 等待对方确认并轮询
  └─ 双方确认 → HERO_SELECT
```

`room.status` 决定顶层页面阶段；`battle.phase`、`battle.available_actions` 和 `battle.response` 只决定战斗页当前的操作区。

## 4. 各状态的渲染与操作

| `room.status` | 必须展示 | 可调用接口 | 轮询规则 |
|---|---|---|---|
| `WAITING` | 房间码、邀请链接、二维码入口、自己的昵称、“等待对手加入” | 仅 GET 刷新 | 每 1–2 秒轮询。 |
| `HERO_SELECT` | 双方昵称、双方“已锁定 / 等待选择”状态、自己的英雄选择器 | `POST /hero`，仅自己未锁定时 | 自己锁定后轮询；未锁定时可低频轮询或只在页面激活时刷新。 |
| `PLAYING` | 双方公开战场、自己的手牌、日志、回合提示、响应区 | 四类动作接口 | 自己有可用操作时停止轮询；等对方或等对方响应时每 1–2 秒轮询。 |
| `FINISHED` | 后端 `battle.result`、双方是否确认再来一局 | `POST /rematch`，仅自己尚未确认时 | 对方尚未确认时轮询；进入新盲选后立即切换。 |
| `EXPIRED` | “房间已过期，创建新房间” | 无 | 停止轮询。 |

`opponent = null` 只允许出现在 `WAITING`。此时前端不得访问任何 `opponent.*` 字段。

## 5. 战斗页视角与操作映射

### 5.1 视角映射

在线模式中，“我”不能写死为 `battle.player`。渲染时必须读取：

```text
self = battle[battle.viewer]
foe  = battle[battle.viewer === "player" ? "enemy" : "player"]
hand = self.hand
```

`self.hand` 恒存在；`foe.hand` 必须不存在。前端发现对手手牌字段存在时，应视为服务端隐私问题而不是把它隐藏后继续渲染。

### 5.2 操作按钮

| UI 操作 | 开启条件 | 请求 |
|---|---|---|
| 打出卡牌 | `battle.available_actions.play_card === true`，且卡牌在 `self.hand` | `POST /actions/card`：`card_id` + 当前 `revision`。 |
| 使用技能 | `battle.available_actions.use_skill === true` | `POST /actions/skill`：当前 `revision`。 |
| 结束回合 | `battle.available_actions.end_turn === true` | `POST /actions/end-turn`：当前 `revision`。 |
| 闪避 | `battle.response.active === true` 且 `respond.dodge === true` | `POST /actions/respond`：`action: "dodge"` + 当前 `revision`。 |
| 反制 | `battle.response.active === true` 且 `respond.negate === true` | `POST /actions/respond`：`action: "negate"` + 当前 `revision`。 |
| 放弃响应 | `battle.response.active === true` 且 `respond.pass === true` | `POST /actions/respond`：`action: "pass"` + 当前 `revision`。 |

按钮是否可用只由服务端的 `available_actions` 与 `response` 决定。能量、回合、技能是否已用等字段可用于显示原因，但不能成为另一套前端合法性判断。

### 5.3 当前回合文案

| 条件 | 页面文案 |
|---|---|
| `battle.response.active` | “等待你响应”并显示服务端给出的响应信息。 |
| `PLAYER_TURN` 且 `viewer=player` | “你的回合”。 |
| `ENEMY_TURN` 且 `viewer=enemy` | “你的回合”。 |
| 其他 `PLAYING` 战斗阶段 | “等待对手行动”。 |
| `battle.result != null` | 交由 `FINISHED` 结果面板处理。 |

在线 PvP 中 `battle.enemy.intent` 恒为 `null`，不得显示 AI 意图、AI 难度或热座交接遮罩。

## 6. 请求、轮询与错误恢复

### 6.1 统一请求处理

所有在线请求使用同源 Cookie。每次写操作应：

1. 读取当前快照的 `room.revision`；
2. 禁用该次动作的重复点击；
3. 提交契约规定的最小 JSON 请求体；
4. 成功后整体替换快照；
5. 失败后按错误码处理；
6. 无论成功失败，恢复界面加载状态。

### 6.2 错误处理表

| 错误 | 前端行为 |
|---|---|
| `STALE_STATE` | 使用响应 `data` 的最新快照替换本地状态；提示“对局已更新，请按当前局面继续”；不自动重发。 |
| `ACTION_REJECTED` | 使用响应 `data` 替换本地状态并展示 `error.message`。 |
| `ROOM_STATE_CONFLICT` | 使用响应 `data` 替换本地状态，切换到其 `room.status`。 |
| `ROOM_AUTH_REQUIRED` / `ROOM_FORBIDDEN` | 停止轮询，显示无法进入房间，回到大厅入口。 |
| `ROOM_NOT_FOUND` / `ROOM_EXPIRED` | 停止轮询，显示房间不可用，提供创建或加入新房间入口。 |
| 网络失败 / 非 JSON 响应 | 保留最后一次成功快照，提示网络错误，并在等待态按退避策略重试；不清空手牌或伪造结果。 |

### 6.3 轮询纪律

- 同一房间页面同一时刻只能存在一个轮询定时器；切页、刷新状态、进入自己回合、终局或过期时必须清理旧定时器。
- 写操作进行中不启动并行 GET，避免动作响应与轮询响应倒序覆盖。
- 收到新快照后，只有当前 `revision` 大于本地 revision 时更新；同 revision 可忽略；小于本地 revision 的响应不得覆盖页面。
- 页面重新获得焦点时立即 GET 一次；页面隐藏时暂停或降低轮询频率。

## 7. 前端测试与接口对照门禁

在线前端实现必须新增独立契约测试，不在旧热座测试中混塞在线逻辑。最低覆盖：

- 正式入口只有人机、创建房间、加入房间，热座不再作为正式入口；
- 所有在线动作请求不含 `seat` 与 `viewer`，且包含当前 `revision`；
- `RoomSnapshot` 是唯一状态输入，`battle.viewer` 驱动 self/foe/hand 映射；
- `WAITING`、盲选等待、等对手、自己响应、结果确认、过期都映射到正确 UI；
- 对手手牌字段不会被读取或缓存；
- `STALE_STATE`、`ACTION_REJECTED`、网络失败都能恢复；
- 轮询仅在等待态工作，且不重复创建计时器；
- 在线模式不渲染 AI 意图、AI 难度或热座交接层。

前端实现开始前，接口契约中的 URL、字段、错误码与 `null` 规则必须已经由后端契约测试锁定。若前端发现“还缺一个字段”，应先修改接口契约并评审，而不是在 JavaScript 中猜测后端行为。
