# 在线 PvP 执行总览与契约门禁

> 上层决策：[产品方向与核心功能](../01-产品方向与核心功能.md)、[在线双人对战架构方案](../02-在线双人对战架构方案.md)。  
> 本文只管理实施顺序、依赖和质量门槛；具体字段以[《在线PvP接口契约-v1》](../../接口契约/在线PvP/在线PvP接口契约-v1.md)为唯一准则。

## 1. 核心纪律

在线 PvP 的实施顺序必须是：

```text
产品与架构确认
→ 在线 API 契约写成并评审
→ 契约测试先落地并失败
→ 后端实现至契约测试通过
→ 前端只按冻结契约接入
→ 双端联调、真实部署与人机回归
```

禁止以下顺序：

- 前端先根据后端代码或猜测字段自行接入；
- 后端临时改字段、错误码或 `null` 语义而不同步契约与测试；
- 用前端判断回合归属、座位身份或卡牌规则来弥补后端缺口；
- 在在线 PvP 尚未验收前，顺带重构人机规则、扩充卡牌或恢复热座入口。

## 3. 分阶段门禁

### 阶段 A：契约冻结

输入：第一、二层产品与架构文档。  
输出：接口契约、请求序列、错误码表和状态 schema。

完成条件：

- 每个接口都有请求、成功响应、失败响应和权限说明；
- 每个状态字段都有“恒在 / 可空 / 条件出现”说明；
- 两个浏览器视角、盲选、响应、过期、版本冲突都有真实示例；
- 新建在线契约测试清单，且所有前端所需字段均能被测试锁定；
- 明确旧 `/api/game` 人机契约不被破坏。

未完成阶段 A，不允许开始在线前端实现。

### 阶段 B：后端共享对局能力

输入：冻结的在线 API 契约。  
输出：房间、身份、盲选、共享战斗、版本控制和结果持久化。

完成条件：

- 在线 API 契约测试通过；
- 两个独立客户端能够加入同一房间；
- 服务端从凭证识别座位，客户端不可传 `seat` / `viewer` 越权；
- 任意动作的旧 `revision` 得到稳定的冲突响应；
- 现有人机测试完整回归。

未完成阶段 B，前端只可制作静态页面和 mock，不得假定后端“以后会返回”的字段。

### 阶段 C：前端契约接入

输入：通过的在线后端契约测试。  
输出：创建、加入、盲选、对局、等待、响应、结算和再来一局页面状态。

完成条件：

- 每一个前端状态都有唯一的数据来源、操作接口和错误恢复规则；
- 操作按钮只依据 `available_actions` 与服务端状态启用；
- 等待态轮询不会在自己的回合无意义高频请求；
- `409 STALE_STATE` 能刷新并恢复，不会把前端卡死；
- 页面不保存、不推导对方手牌与战斗规则。

### 阶段 D：双端联调与交付

输入：后端与前端各自通过契约检查。  
输出：真实双设备对局证据、部署配置和回归记录。

完成条件：

- 两个独立浏览器完整进行一局；
- 私有手牌、盲选、响应、再来一局和刷新恢复均人工验证；
- 已确认结果只写入一次；
- 人机模式回归通过；
- 部署环境使用持久数据库、非开发密钥和非 debug 配置。

## 4. 接口变更纪律

在线 PvP 契约发布为 v1 后，遵守：

- 可以增加可选字段、可选接口和新的错误码；
- 不可删除、改名或改变既有字段含义；
- 不可把“恒在字段”改为条件字段，或改变 `null` 语义；
- 不可改变已发布错误码的 HTTP 状态；
- 若必须发生破坏性变更，创建 v2 契约并同时维护迁移说明与前端切换计划；
- 任何契约改动必须同一次更新：契约文档、契约测试、相关前端对接文档。

## 5. 代码与测试责任边界

| 责任 | 应在后端完成 | 前端不得完成 |
|---|---|---|
| 玩家座位识别 | 从凭证确定当前座位 | 传入或伪造 `seat` |
| 手牌隐私 | 只序列化当前 viewer 的手牌 | 隐藏已收到的对方手牌 |
| 回合与响应合法性 | 调用 `BattleState` 并拒绝非法动作 | 根据本地猜测阻止或放行规则 |
| 并发控制 | 校验 revision、事务写入 | 假设请求一定按顺序返回 |
| UI 操作权 | 输出 `available_actions` | 用生命值、能量等字段自行推导完整权限 |
| 结果保存 | 房间状态转终局时只写一次 | 浏览器看到结果时写数据库 |

## 6. 第三层完成定义

第三层文档完成不等于代码已完成。文档阶段完成的标志是：

- 本目录全部五份文档互相引用且没有字段冲突；
- 在线 API 契约可独立交给前端或后端实施者，不需要再口头补充；
- 每条产品核心流程都有“接口序列 + 后端责任 + 前端状态 + 验收方式”；
- 现有热座相关文档被明确标记为历史实现，而不是在线 PvP 的接口来源；
- 新文件归属遵循项目的文件组织规范。
