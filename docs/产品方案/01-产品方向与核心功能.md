# 产品方案第一层：产品方向与核心功能

> 状态：已确认。  
> 范围：只定义产品目标、正式模式、核心体验与边界；不在本文确定数据库、接口、部署和具体开发步骤。

## 1. 产品定位

本项目是一个以 Python / Flask 为核心的轻量级网页卡牌对战游戏。

它不再只是“玩家打电脑”的单机演示，而是支持两类完整对局的浏览器卡牌游戏：

- **人机对战**：单人选择英雄和 AI 难度，体验现有的策略卡牌玩法。
- **在线双人对战**：两名真人用各自的手机或电脑，通过房间链接进入同一局回合制对战。

产品的核心价值是：玩家通过能量、手牌、装备、响应和时机判断进行真实对抗，而不是单纯比较数值或轮流点击按钮。

对课堂展示而言，项目应当能清楚体现：

- Python 后端拥有唯一、可信的战斗规则；
- Web 服务能够维护两名玩家共享的一局游戏；
- 双方私有手牌与公开战场信息能够正确隔离；
- 游戏提供真实的真人对抗，而不是形式上的同机热座。

## 2. 正式模式与产品入口

开始页的正式入口固定为：

```text
开始游戏
├─ 人机对战
├─ 创建双人房间
└─ 加入双人房间
```

### 2.1 人机对战

人机对战保留为单人基础模式：

- 玩家选择英雄与 AI 难度；
- 保留 AI 意图预告和难度差异；
- 使用现有的英雄、卡组、能量、装备、响应和结算规则；
- 本轮在线 PvP 改造不得改变其规则和体验。

### 2.2 在线双人对战

在线双人对战是本阶段体现“对抗性”的正式模式。

- 玩家 1 创建房间，获得房间码、邀请链接和可选二维码；
- 玩家 2 通过邀请链接或房间码加入；
- 双方各自在自己的设备上选择英雄并进入同一局；
- 双方共享战场、战斗日志和结算结果；
- 双方只看到自己的手牌；
- 双方独立进行出牌、结束回合与响应操作；
- 对局结束后，双方可在同一房间内再来一局。

第一版采用**邀请房间制**，不做陌生人自动匹配。邀请房间已经能满足课堂中的真人 BvB，同时避免引入排队、取消、空房、恶意占坑和复杂掉线恢复等不必要问题。

### 2.3 原双人热座

原“同一设备轮流操作”的双人热座模式进入冻结状态：

- 不再作为正式产品入口；
- 不再投入新的交互或玩法优化；
- 暂时保留已有规则与代码，直到在线双人对战稳定后再决定是否删除；
- 后续产品、前端和验收均以在线双人对战为准，不再以交接设备流程为目标。

## 3. 统一规则原则

人机对战和在线双人对战必须共用同一套核心规则：

- 相同的英雄池与英雄专属卡组；
- 相同的能量、先手修正、抽牌和手牌上限；
- 相同的装备、条件牌、消耗、闪避和反制；
- 相同的胜负与回合上限结算；
- 相同的公开信息边界。

两种模式唯一的区别是对手的决策来源：人机模式由 AI 决策，在线双人模式由另一位真人决策。

**在线 PvP 是更换对手接入方式，不是新建一套战斗规则。**

## 4. 在线双人对战的核心体验

一局完整的在线对战至少应覆盖以下体验：

1. 玩家创建房间并分享邀请信息；
2. 另一位玩家成功加入等待中的房间；
3. 双方以临时昵称识别彼此，无需注册账号；
4. 双方各自选择英雄；
5. 双方在各自设备上看到同一战场，但只看到自己的手牌；
6. 轮到自己时，可以出牌、使用技能或结束回合；
7. 对手打出可响应的牌时，防守方在自己的设备上决定闪避、反制或放弃；
8. 对方操作后，等待方能及时看到战场与日志更新；
9. 对局结束时，双方看到同一份胜负结果与回合数；
10. 双方可在当前房间内发起下一局，无需重新分享链接。

第一版不承诺毫秒级同步。作为回合制游戏，短间隔状态刷新能够满足体验；产品优先保证双方始终基于同一份可信对局状态操作。

## 5. 本阶段明确不做

为保持课堂 Python 项目的边界，本阶段不做：

- 登录、账号、好友和社交关系；
- 陌生人自动匹配、排位、排行榜；
- 实时聊天、观战、直播；
- 多人房间、组队、锦标赛；
- 新英雄、新卡牌或额外数值平衡改动；
- 复杂动画、音效或付费与收集系统；
- WebSocket、复杂断线恢复与跨区性能优化。

现有玩法已经能够支撑策略和博弈；本阶段的重点是为真人对抗提供正确、自然的承载方式。

## 6. 第一阶段产品验收

在线双人对战完成后，以下场景应成立：

- 两部设备通过同一域名访问游戏；
- 玩家 A 能创建房间，玩家 B 能通过链接或房间码加入；
- 双方进入同一局战斗，但无法查看对方手牌；
- 任一方操作后，对方能看到正确的公开状态和战斗日志；
- 闪避、反制等响应只能由实际防守方操作；
- 双方能完整打完一局，并得到一致的结果；
- 双方可以在同一房间内再来一局；
- 人机对战既有流程和规则不受影响；
- 全程不需要传递设备。
