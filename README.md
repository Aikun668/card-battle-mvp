# Python 卡牌对战游戏

这是一个以 Python 为主的轻量级网页卡牌对战游戏项目。

当前阶段已经完成后端 MVP 和 JSON 接口。现有 HTML 页面只保留为 `/demo` 临时联调入口，正式前端后续由插件构建。完整需求见 [docs/mvp.md](docs/mvp.md)，玩法和交互规则见 [docs/interaction-design.md](docs/interaction-design.md)，接口约定见 [docs/api-contract.md](docs/api-contract.md)。代码实施步骤见 [实现计划](docs/superpowers/plans/2026-09-18-card-battle-mvp.md)，验收与质量门槛见 [验收文档](docs/claude-builder/acceptance.md)，外部 Claude Code 执行交接见 [Claude Code 交接](docs/claude-builder/claude-code-handoff.md)。

## 一句话玩法

玩家选择一个角色，挑好电脑难度，与电脑对手进行一局 3–5 分钟的回合制战斗，在有限能量下决定攻击、防守和治疗的顺序，最终击败对手。

## MVP 范围

- 单人对战电脑 AI：简单 / 中等 / 困难三档，只影响电脑的选牌质量，不改变数值，默认中等；
- 3 个角色：战士、法师、游侠，双方从同一英雄池获得英雄；
- 8 种卡牌：斩击、重击、护盾、治疗、火球，只在响应窗口使用的闪避，以及两张装备牌长剑和铁甲；
- 三个英雄各持一副 15 张的专属卡组，打法差异来自卡组构成，不做抽卡、卡牌收集和卡组编辑；
- 每局先手由 RNG 公平决定，双方规则完全对等；
- 玩家回合、电脑回合、响应窗口、胜利、失败、平局等战斗状态；
- 后端 JSON 接口；HTML 开始页、角色选择页、战斗页、结果页仅作为 `/demo` 联调工具；
- 战斗日志、能量限制、生命值、护盾和胜负判断。

## 技术方向

- Flask

## 三副英雄卡组

每副卡组固定 15 张，只从同一份牌表里取牌，打法差异全部来自张数配比：

| 英雄 | 卡组构成 | 打法 |
| --- | --- | --- |
| 战士 | 斩击 6、重击 3、护盾 2、治疗 1、闪避 1、长剑 1、铁甲 1 | 牌多血厚，靠护盾和治疗把对局拖长 |
| 法师 | 火球 3、重击 3、斩击 4、护盾 2、治疗 1、闪避 1、铁甲 1 | 三张火球抢速度，能量够就能连出高伤害 |
| 游侠 | 斩击 8、重击 2、护盾 1、治疗 1、闪避 2、长剑 1 | 八张 1 费斩击配长剑，最容易一回合连打 |

## 人机规则对等

玩家和电脑使用同一套规则：同一个英雄池、每人一副 15 张英雄专属卡组、同样的 3 点能量、6 张手牌上限、起手 5 张、护盾跨回合累计、抽牌与弃牌规则、每回合一次的英雄技能、每回合一次的装备加成，以及双向的闪避响应。每局的先手由 RNG 公平决定，电脑抽到先手时它开局的回合在创建对局时就已经跑完。

电脑和玩家一样按自己的英雄领卡组：它选到法师就摸火球，选到游侠就摸八张斩击，不存在“电脑用加强牌”这回事。

公开信息也对称：双方的英雄、生命值、护盾、能量、技能状态和装备都能在接口和页面上看到，只有手牌保持私有。电脑的决策只看得到公开信息和自己的手牌，玩家手牌与抽牌堆不在它的视野里，困难模式的一步前瞻也只按公开牌表估算威胁。

## 装备

长剑和铁甲按英雄入组：长剑在战士和游侠的卡组里，铁甲在战士和法师的卡组里，每副卡组里同一件装备最多 1 张。它们和普通卡一样花 1 点能量打出，打出后挂到角色身上，不进入弃牌堆：

- **长剑**（武器槽）：每回合第一次斩击 +2 伤害，重击和火球不受影响；
- **铁甲**（护甲槽）：每回合第一次受到的伤害 -2，先于护盾生效，对英雄伤害技能同样有效；
- 两个加成都是每回合一次，触发过就等下一个自己的回合；装备本身跨回合保留，本轮没有替换和摘下的规则；
- 装备是公开信息，双方都能看到对面装了什么；装备牌仍然走 `POST /api/game/actions/card`，没有新接口。

## 电脑 AI 与难度

电脑不使用固定的 `if / elif` 优先级表。每个动作都按同一套流程处理：枚举合法候选（费用足够的手牌 + 英雄技能 + 结束行动）→ 按实际收益评分 → 排序 → 按难度选择，打完一张牌后用最新状态重新评估，因此电脑和玩家一样可以在一个回合内连续出牌。闪避牌不进入主动候选，只在响应窗口里参加选择。

伤害牌还会做连招规划：评分时把"这张打完之后，剩余能量还能打出的最优伤害序列"一起算进去，所以电脑会用"技能 10 + 斩击 6 = 16 伤"而不是单张火球 14 伤收尾。规划深度按难度分层——简单不规划（保持逐张贪心）、中等看一手、困难规划到打光；武器装备也参与规划，但只统计它能加成的伤害牌。规划是纯查询：只读电脑自己的手牌与公开信息，不改动真实对局状态。

- 困难：固定选择评分最高的行动，并做一步前瞻（按公开牌表预判玩家下回合能否击杀自己），伤害牌规划到打光；
- 中等：大概率选最优，偶尔选次优（默认），伤害牌看一手；
- 简单：在高分候选中更容易选到非最优项，不做连招规划。

三档难度共用完全相同的卡牌数值、生命值、能量和抽牌规则，不靠数值作弊，也不读取玩家的隐藏手牌。所有随机都走可注入的种子随机数，便于测试复现。

## 开发原则

先把一局完整战斗跑通，再增加视觉效果或扩展玩法。所有卡牌效果、能量消耗和胜负判断都应能在代码和测试中明确验证。

## 本地启动

使用系统 Python 直接安装依赖并启动开发服务器：

```bash
pip install -r requirements.txt
flask --app app:create_app run --debug
```

启动后访问 `http://127.0.0.1:5000/` 查看服务信息，访问 `http://127.0.0.1:5000/demo` 打开临时联调页面。正式前端使用 `/api` 接口，具体见 [API 接口约定](docs/api-contract.md)。SQLite 数据库默认写入 `instance/card_battle.sqlite3`，首次启动时会自动建表。

如果希望隔离依赖，也可以走标准虚拟环境流程：

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
flask --app app:create_app run --debug
```

## 运行测试

```bash
pytest -v
```

测试覆盖角色、卡牌、战斗状态、装备结算、电脑 AI、Session 序列化、SQLite 结果表、公开状态隐私边界和 Flask 路由。

## 演示流程（6 步）

1. 在开始页点击“开始游戏”，选一个角色，再选电脑难度（默认中等），点击“确认角色”。进入战斗页后，电脑名称旁会显示本局难度，刷新不会丢失。
2. 在战斗页查看双方状态：电脑英雄名、双方生命值、护盾、能量和技能状态都在页面上，只有手牌是各看各的。
3. 使用一张手牌，确认电脑生命值下降、能量扣减、日志出现记录。
4. 试着点击一张能量不足的卡牌或本回合已用过的技能按钮，确认按钮被禁用或页面给出“能量不足”提示。
5. 点击“结束回合”，电脑按自己的能量连续出牌（可能不止一张）；它打出的伤害牌如果被你的闪避拦下，页面会先弹出“使用闪避 / 放弃响应”，选完再继续。
6. 当任一方生命值归零，或打满 10 回合上限时进入结果页。打满上限时先比生命值，血多者胜；生命值相同再比剩余护盾；两者都相同才是平局。点击“再来一局”回到角色选择页，重新开始新一局战斗。

刷新 `/demo/battle` 不会重复执行上一条战斗操作：临时联调页面的所有 `POST` 路由都遵循 Post/Redirect/Get 约定。
